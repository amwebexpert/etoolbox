A file named `pump-test.ts` that exports `usePumpTest` — a hook — makes the reader guess what kind of thing they're opening before they open it. This repo's convention exists so the filename alone tells you: `use-*` is a hook, `*-page.tsx` is a route page, `*-dialog.tsx` is a dialog, `*-provider.tsx` is a context provider — and a bare `utils.ts`/`types.ts` at any depth is a name so generic it stops being findable by search the moment a second one exists anywhere in the tree.

**Fix:**
1. Hook file: rename to `use-<name>.ts`, matching the hook's own name in kebab-case.
2. Page/Dialog/Provider-suffixed component: rename the file to end with the matching suffix (`-page.tsx`, `-dialog.tsx`, `-provider.tsx`) — and check word order matches the export name (`TestRequestCreatePage` belongs in `test-request-create-page.tsx`, not `test-request-page-create.tsx`).
3. Generic root-level basename (`utils.ts`, `types.ts`, `helpers.ts`, `constants.ts`, `config.ts`, `client.ts`): prefix it with its domain — `<domain>.utils.ts`.
4. After renaming, update every import that references the old path.

**Known, deliberate exception**: a file whose auto-generated content is owned by another script (e.g. `src/constants.ts`, regenerated by `scripts/generate-version.ts`) is exempt — its name is dictated by the generator, not by this convention; those paths are excluded in `eslint.config.js`'s `globalIgnores`, not disabled per-line.

**AVOID**: renaming a file that exports *multiple* hooks/components (a store file with several selector hooks, a shared utils module) to match just one of them — this rule deliberately only fires when a file has exactly one primary value export to name itself after; a multi-export file's name should describe the whole module, not one export.
